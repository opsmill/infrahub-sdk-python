Sync protocols generated by `infrahubctl protocols` now inherit the `*Sync` variant of every base class that has one, instead of only `CoreNode`, `CoreProfile` and `CoreObjectTemplate`. A class inheriting another core kind (for example `BuiltinIPAddress` or `LineageSource`) previously kept the async base in its sync output, so its `save`, `delete` and `create` methods were typed as async and a correct sync call was reported as a missing `await`. Regenerate with `infrahubctl protocols`: sync classes that inherited an async base will now expose the sync methods, which may surface new type errors in code that relied on the old async signatures.
