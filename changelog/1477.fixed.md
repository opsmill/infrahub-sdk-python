A tracking run with `delete_unused_nodes=True` (as used by generators) now deletes unused nodes that hold each other through a mandatory relationship in one run.

The cleanup deleted the unused members in the order the group returns them, which is creation order. A node created first, such as an IP address, was deleted before the unused node that holds it through a mandatory relationship, such as a BGP session. The server refused the delete, so the run failed with `TrackingGroupCleanupError` and the node was only deleted by the next run.

The cleanup now deletes a node before the nodes it holds through a mandatory relationship. The order between kinds comes from the cached schema and sends no request. Nodes of a kind with a mandatory relationship to its own kind (or kinds that hold each other) are ordered from their peers, which takes one query per such kind. A member that a node outside the group holds is still refused, kept in the group and reported in `TrackingGroupCleanupError`.
