Fixed the URL paths used by `file_object_content`, `file_object_content_by_id`, and `file_object_content_by_hfid` Jinja2 filters so they match the actual backend routes. All three filters were 404ing because the SDK hardcoded `/api/files/*` but the backend serves these endpoints under `/api/storage/files/*`. Added happy-path unit tests for `file_object_content_by_id` and `file_object_content_by_hfid` (both string and list forms) so similar contract drift is caught in CI.
