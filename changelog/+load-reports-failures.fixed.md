`infrahubctl load` now reports the tasks that failed. `execute_batches` bound the `(node, result)` pair its batch yields to a single name, so every check of the result looked at a tuple rather than at the result, which no task can ever produce. A failed task was therefore counted as a success: nothing was printed, `--continue-on-error` had nothing to report, and the exception object was returned in the list of imported results. Failures now print with the server's errors and are kept out of that list, and an import that does not pass `--continue-on-error` raises on the first one as it always intended to.
