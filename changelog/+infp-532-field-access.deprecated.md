Reading a field that the SDK didn't fetch now emits `FieldNotLoadedWarning` (a `FutureWarning` from `infrahub_sdk.exceptions`) and still returns `None` or `[]` as before. In infrahub-sdk 2.0 the same read will raise `FieldNotLoadedError`. This affects, for example, the `peers` of a relationship of cardinality many read after a default `get()`, a field left out with `exclude`, and a field you never set on a node that has since been saved. Such reads already returned an empty value whatever the server held.

To fix a read, add the field to the query with `include` or `only`, call `fetch()` on the relationship, or query with `prefetch_relationships=True`, and check `is_loaded` only where you can't know how a node was fetched. To find these reads before 2.0, run your tests with `pytest -W error::infrahub_sdk.exceptions.FieldNotLoadedWarning`, or call `warnings.simplefilter("error", FieldNotLoadedWarning)` in a script.
