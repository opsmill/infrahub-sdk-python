Added an `only` parameter to `get()`, `filters()` and `all()` on `InfrahubClient` and `InfrahubClientSync`. It queries exactly the named attributes and relationships plus `id`, `display_label` and `__typename`, so the query no longer grows with the schema. Naming `hfid` adds the server's HFID to the query and to the raw payload returned by `get_raw_graphql_data()`; `node.hfid` is still computed from the fields that make up the human-friendly ID of the kind, and is `None` when one of them wasn't fetched. A named relationship returns references to its peers, or their default set of fields with `prefetch_relationships=True`. Combining `only` with `include` or `exclude` raises `SelectionConflictError` before any request, and a name that isn't a field of the kind raises `SelectionFieldNotFoundError` before the query is sent. Reading a field that a node returned by `only` doesn't carry raises `FieldNotLoadedError`.

`RelatedNode.fetch()` and `RelationshipManager.fetch()` accept `only` and `exclude` to choose which fields of the peers to query; with peers of several kinds, each kind is asked for the named fields it defines, and a kind that defines none of them isn't queried and its peers stay references. Every attribute and relationship also has an `is_loaded` property that tells whether the SDK knows its value.
