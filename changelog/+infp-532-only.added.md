Added an `only` parameter to `get()`, `filters()` and `all()` on `InfrahubClient` and `InfrahubClientSync`. It queries exactly the named attributes and relationships plus `id`, `display_label` and `__typename` (name `hfid` to add the HFID), so the query no longer grows with the schema. A named relationship returns references to its peers, or their default set of fields with `prefetch_relationships=True`. Combining `only` with `include` or `exclude` raises `SelectionConflictError` before any request, and a name that isn't a field of the kind raises `SelectionFieldNotFoundError` before the query is sent. Reading a field that a node returned by `only` doesn't carry raises `FieldNotLoadedError`.

`RelatedNode.fetch()` and `RelationshipManager.fetch()` accept `only` and `exclude` to choose which fields of the peers to query; with peers of several kinds, each kind is asked for the named fields it defines. Every attribute and relationship also has an `is_loaded` property that tells whether the SDK knows its value.
