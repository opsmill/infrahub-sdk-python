The client store now keeps one entry per node and branch. Before, each query that returned a node already in the store, such as a repeated `client.get()`, `client.all()` or `client.filters()`, added another copy and kept the previous one in memory, so a long-running process that reused one client used more memory on every query. A lookup by ID, HFID or key returns the copy from the latest query, and `client.store.count()` now returns the number of distinct nodes. When the new copy has no HFID, for example from a query with `only` that did not request it, a lookup by the earlier HFID now returns the new copy instead of the earlier one. A related node returned with a query, for example with `prefetch_relationships`, `include` or `only`, replaces an earlier related copy but not a node returned by a query for its own kind or stored by `save()`, so it does not overwrite a node loaded with more fields. Looking up a node on a branch the store does not hold no longer adds an empty entry for that branch.
